# Jotta Edit 1.1.0 — Desktop and Web/PWA source

## New: offline-first Web edition

The same editor is now available as a separate **installable web app** using
Monaco, custom themes, Prettier, Emmet, IndexedDB session recovery and browser
project workspaces. Use **Download file** (also in the File menu) to download the active document with unsaved edits. Save keeps edits in the workspace; Export ZIP downloads saved project files. Live preview controls are disabled in the web version. Use **New workspace**, **Import folder/ZIP**, **Export ZIP**,
or native **Open folder** where supported. The desktop and web builds share application version `1.1.0`.

```bash
npm install --no-audit --no-fund
npm run dev:web        # development browser app
npm run build:pwa      # deployment output: web-dist/
# alternatively: ./scripts/build-web.sh
# deploy the contents of web-dist/ or the DEPLOY ZIP generated by build-web.sh
# DO NOT upload web/ or the source ZIP to the server
```

For installation, offline behaviour, file safety and deployment instructions,
see [docs/web-app.md](docs/web-app.md).


Jotta Edit is a lightweight code editor built with Electron and Monaco. It includes an Explorer, multiple tabs, Emmet, Prettier and optional local language-server completion. Its Flatpak ID is **`pt.jotta.edit`**.


## GitHub sync

Open the Git button in Explorer or File → GitHub sync. Connect a fine-grained token with access to selected repositories and Contents read/write permission. Choose a repository and branch, then create a managed checkout or use a folder without `.git`. Review incoming and local changes, resolve conflicts and select new files explicitly before committing. Use Pull updates or Commit & sync selected. The token remains in memory for the session.

Desktop checkouts use ordinary folders without Git metadata; web checkouts use browser storage. No Git executable or authentication server is required. See [GitHub setup and sync limits](docs/github-sync.md).

## Live preview and Explorer creation

Preview static HTML projects in your chosen browser with live updates from unsaved edits. Choose System default, Firefox or Chrome in Preferences → General. Right-click an Explorer folder, the project root or empty Explorer space to create a new file or folder. Application menus and sidebars no longer allow text selection; editor content and input fields remain selectable.

## 1.0.1 — Custom syntax theme editor

Under **Preferences → Themes**, duplicate any built-in palette to create an editable copy. Change editor/background/foreground, popups, borders and syntax token colours using the shared colour mixer or HEX fields. Themes can be renamed, reset, removed, exported as JSON or imported from a Jotta Edit theme JSON file. Built-in presets are read-only; custom themes remain available between sessions. The same Themes tab also allows separate dark/light **interface colour** overrides (workspace, panels, text, borders and accent). Explorer icon colours stay configurable on the Explorer tab and inherit their custom theme's original icon palette unless overridden.

Under **Preferences → Editor → Colour display**, choose the default colour squares or **Colour value background** to highlight HEX, RGB/RGBA and HSL values with their own colour. Text contrast adapts to transparency and the editor theme. Click the `#` or function name (`rgb`, `rgba`, `hsl`, `hsla`) to open the colour picker; click the numbers to edit them normally. The preference applies immediately and persists in the desktop and web apps.

## Plain Text word matching and formatting line width (v1.0.0 source update, no version change)

Under **Edit → Preferences → Editor**:

- **Plain Text matching words:** default **Only when a word is selected** (double-click a word to highlight matches). Optionally highlight when the caret is inside the word or disable matches. Other languages retain their code-highlighting behaviour.
- **Formatting line width:** defaults to **No preferred limit**; optional **80**, **100**, or **120** columns. A formatter print width is a guideline rather than a strict maximum; the no-limit setting uses a very large value (10,000 columns).
- HTML formatting preserves typed paragraph text (`proseWrap: 'never'`), avoiding arbitrary changes to prose line breaks. **Word wrap** is separate: it changes the display only, without writing newline characters to the file.

## Word wrap and restore open tabs (v1.0.0 source update, no version change)

- Go to **Edit → Preferences → Editor** and enable **Word wrap (fit to editor width)**. The `Alt+Z` shortcut and **View → Toggle Word Wrap** stay available. The preference takes effect immediately and is restored on startup.
- When Jotta Edit closes or is restarted, the current tabs are retained — including **untitled documents that were never saved**, and changes to saved files that have not yet been written to disk. Tab order and the selected tab are restored.
- Drafts are backed up periodically (about 650 ms after the last change), with a final write before normal exit. Recovery data is saved locally in Electron's per-user application data directory, in `session.json`. On Windows that is normally under `%APPDATA%`; on Linux, within the relevant user app data area (Flatpak's sandbox when applicable).
- Unsaved buffers are **not** automatically saved back to their original files. When restored, they remain marked as changed until explicitly saved. Individual tab closure still asks whether to save/discard changes; **quitting the app preserves drafts without prompting**.
- If a previously opened file has moved or disappeared, any recovered unsaved content is opened as an untitled `recovered-...` tab rather than discarded. Clean files that are no longer available are not reopened.
- Recovery snapshots contain unsaved code in readable local files. Treat application data as private and include it in your backups if recovery after a device failure matters. Forced termination can lose the most recent edits made since the last snapshot.

## Explorer icon colours (v1.0.0 source update, no version change)

Open **Edit → Preferences → Explorer**. The **Explorer icon palette** defaults to **Follow code syntax theme**, which automatically coordinates file/folder colours with the selected code-highlighting palette while leaving the application's own UI styling unchanged.

You can override the palette independently with presets inspired by **Material Icons**, **VS Code Seti**, **Catppuccin Mocha / Latte**, **Monokai Pro**, or **GitHub**, or choose **Monochrome**. The existing **Explorer icon colours** menu continues to set colours separately by file type; those saved manual choices always take precedence. Click **Automatic** for a file type to return to the selected palette's default colour.

Icon shapes are the original supplied SVGs, not copies of third-party icon assets. Automatic colours are adjusted for contrast against the Explorer sidebar in both light and dark UI modes. See [`docs/explorer-icon-palettes.md`](docs/explorer-icon-palettes.md) for details.

## Syntax highlighting themes (v1.0.0 source update, no version change)

Open **Edit → Preferences → Code syntax theme** to choose a Monaco code-highlighting palette. This setting is independent of the application light/dark mode; changes apply immediately to all open files and are saved for future sessions. The default **Follow interface (Jotta)** retains Jotta's existing dark/light Monaco highlighting and tracks the interface mode.

Included locally (no external theme packages or network needed): **Jotta Dark**, **Jotta Light**, and palettes inspired by **Monokai**, **One Dark**, **Dracula**, **Nord**, **Tokyo Night**, **Catppuccin Mocha**, **GitHub Light** and **Solarized Light**. The colours are adapted for legibility and are not copies of official third-party theme files. The setting includes a preview and works in English and Portuguese (Portugal).

## Features and safety notes

- **Recent workspaces:** Open File → Recent Workspaces, use the command palette, or pick a recent project on the welcome screen. Removing an entry only removes it from the list. Browser folder access may need permission again.
- **Project settings:** In Preferences → Editor, enable “Use project-specific editor settings” for indentation, tab width, word wrap and formatting. Disable it to restore global defaults. Settings are stored locally, with no project configuration files. Switching projects preserves open buffers.

- **Colour mixer:** Adds Saturation and Lightness sliders alongside Hue and Opacity. Drag the dialog by its header; click a colour marker in CSS code to reopen it. Works in unsaved documents too.
- **Automatic syntax selection:** Unsaved documents conservatively identify common languages (CSS, HTML, JSON, JavaScript, PHP, XML, Python, SQL, Markdown and shell) from their contents. A saved document's extension retains priority.
- **Explorer context actions:** Right-click a file/folder to **Rename…** or **Move to Trash…** (both use the app's own dialog). `F2` also renames a focused entry. Deletion requires confirmation and preserves the item in system Trash on desktop or project-local Trash in the browser.
- **Explorer drag-and-drop:** Drag an entry onto a folder or the workspace heading to move it on disk. The operation never overwrites an existing entry and does not allow moving a directory into itself. Moving across different drives/filesystems is not supported; an OS error leaves the original in place. This is *internal Explorer-to-Explorer drag-and-drop*, not importing files from the desktop.
- **Open files:** Files whose paths change are updated in open tabs. Modified documents must be saved or the operation is cancelled. Files deleted from disk are closed in the editor.
- Updated the SVG-file icon and the Explorer's add-folder icon with the supplied SVGs. The Explorer's existing × remains a **view-only** action, separate from Delete.

## Build targets

### Linux Flatpak

```bash
./scripts/build-flatpak.sh
```

Flatpak bundles include AppStream metadata for KDE Discover: **Jotta Edit**, developer **João Jotta**, and the **GPL-2.0-or-later** licence. The metadata is validated when running the build script.

Expected Flatpak bundle: `release/Jotta-Edit-1.1.0-linux-x86_64.flatpak`

Install with desktop integration:

```bash
./scripts/install-flatpak.sh
```

This installs the Flatpak for the current user and creates a KDE-compatible
`pt.jotta.edit.desktop` entry with a valid `Exec=` command and `%F` argument
support. It refreshes the KDE application cache but does not change existing
file-type defaults.

If KDE reports `Could not extract executable name from ''` when using
**Open With**, repair the entry without rebuilding:

```bash
./scripts/repair-kde-open-with.sh
```

Optionally, set Jotta Edit as the default TXT editor:

```bash
./scripts/repair-kde-open-with.sh --set-default
```

If the file still fails to open, test the app directly:

```bash
flatpak run pt.jotta.edit "$HOME/path/to/example.txt"
```

The repair script creates a timestamped backup of any existing user desktop
entry. Select **Open With → Jotta Edit** in Dolphin again after the repair.

### Live preview

In the desktop app, use the Live Preview button beside Format Document, or Tools → Open Live Preview. The active HTML or PHP file opens in your browser; when editing CSS or JavaScript, preview uses the project's index.html or index.php (or another HTML/PHP file). Untitled HTML can also be previewed. Changes reload automatically as you type without saving, including linked CSS and JavaScript. Requested files changed on disk also trigger a reload. Use Tools → Stop Live Preview to stop the local server.

Choose System default, Firefox, or Chrome under Preferences → General → Live preview browser. The selected browser must be installed. Preview serves project files on loopback. PHP files run through the PHP development server and require `php` on your system PATH (on the host for Flatpak). Save PHP changes before previewing them; PHP executes saved files, including project includes, while static HTML/CSS/JavaScript can use unsaved editor content. Local PHP previews enable PHP error display to reveal missing includes, extensions or database failures. PHP responses preserve query strings, form submissions, response headers and session cookies. Frameworks that need their own development server or rewrite rules still require that server. Project HTML with a restrictive Content Security Policy may block the injected reload script. External browser launching is available in the desktop app.

Explorer's **Move to Trash** uses the system Trash/Recycle Bin on desktop. In browser workspaces, deleted entries are preserved under the project's hidden `.jotta-trash/` folder with `restore.json` recording the original path. Enable hidden files in Explorer to find these backups and move the saved entry back to its original folder (use the operating-system file manager for native browser folders).

## Project search and replace

Use **Ctrl+Shift+F** or the magnifying glass beside Explorer to open the search sidebar. **Ctrl+Shift+H** opens the replacement field. Search literal text, optionally matching case or whole words, across project text files and unsaved open documents. Click a matching line to open it at the match.

Enter replacement text to preview each line before and after the change. Select the files to change, then choose **Replace selected**. Changes open as unsaved editor tabs; use **Undo replacement** to undo the batch before further edits, or **Save changed files** to write those tabs. Normal per-file Undo remains available. Changes to a previewed open document invalidate the search, and replacements recheck closed files before editing.

Search skips binary, unreadable and text files larger than 1 MB. Results report skipped files and incomplete scans; scanning is bounded at 8,000 files, 20 MB of text and 5,000 matches per file. Previews show the first 20 matching lines per file, while replacements cover every match in the selected files. A replacement batch must fit the existing 50-tab and 40 MB session recovery limits.
